### 画布展示状态覆盖与交互脚本

#### 一、用途与基本约束

项目设计态提供全局响应式对象 `window.__LINGSTYLE_DISPLAY_MOCK__`，用于临时覆盖列表、加载、错误等 UI 展示状态；组件在渲染中读取其属性后，重新赋值顶层属性可触发 UI 更新。

覆盖只影响画布显示，不改变正式数据源、请求、状态更新或其他业务流程；未设置覆盖值时沿用原有展示逻辑。

#### 二、任务范围与画布标识

画布包括独立渲染的页面，以及通过 `popupRef` 包裹并独立渲染的弹窗、抽屉等浮层。只分析目标画布内的组件：页面引用的 `popupRef` 浮层不自动纳入页面任务，其普通子组件归属该浮层画布。选区或其他需求按指定节点和需求描述确定范围，画布标识不扩大处理范围。

交互脚本以画布标识确定归属，统一使用以下规则：

- 页面画布：`page:${filename}:${widgetName}`；
- 浮层画布：`popup:${filename}:${widgetName}`。

`filename` 是画布根组件定义所在文件的完整路径，不截短为相对路径；`widgetName` 根据该根组件的源码定义确定：

- 包装调用赋值给变量时，使用声明的变量名。例如 `const EditUser = popupRef(...)` 或 `export const EditUser = popupRef(...)`，组件名均为 `EditUser`；`export default EditUser` 不改变该名称。
- 直接默认导出包装调用时，例如 `export default popupRef(...)`，使用文件名去掉扩展名后的名称；若文件名为 `index`，则使用直接父目录名。例如 `/project/components/EditUser.tsx` 和 `/project/components/EditUser/index.tsx` 均使用 `EditUser`。名称保留原有大小写。

不要使用中文标题、调用处的导入别名、JSX 行号或路由代替组件名。同一组件定义被多个路由或页面引用时，沿用同一个画布标识；普通子组件不单独生成画布标识。

编写交互脚本时，优先原样使用任务上下文或画布容器提供的当前画布标识；未提供时，根据源码中的画布根组件定义确认类型、完整文件路径及组件名，按上述规则生成。仍无法确认时，不填写或改动 YAML，并说明原因；不得使用占位标识，或借用、改写其他画布的标识。

#### 三、展示覆盖接入规则

按任务选择有意义的可变化展示数据，不要求覆盖所有 Hook 返回值。React 状态或自定义 Hook 的展示值可以作为候选；由 props 传入时，沿调用链找到状态、Hook 返回值或请求结果等来源，在来源的展示值选择处接入覆盖。

先按以下规则排除可直接操作且稳定可见的交互状态及控件自身数据，再判断展示差异；排除规则优先于内容变化、区域显隐、布局变化、列表和空态等一般规则，不因使用 `useState`、接口数据、遍历或条件渲染而自动接入：

- **可直接操作且稳定可见的交互状态默认排除**：若用户能在当前画布通过已有交互直接到达目标状态，且该状态可持续观察、不依赖额外数据或外部条件，则不接入展示覆盖，也不生成场景。排除范围包括该交互直接产生的派生展示和联动结果，即使影响控件外内容、区域显隐或布局，也不因此纳入覆盖。用户明确要求模拟时除外。判断时须确认当前画布中的操作入口和状态更新链路有效，不能仅凭源码中存在事件处理函数就认定目标状态可直接查看。
- 输入框、下拉框、单选框、复选框等控件，若变化仅影响自身输入、选中样式或字数计数，不主动接入，也不生成场景；仅参与提交、请求参数或事件处理的数据同样如此。用户明确要求时除外。
- **控件选项数据默认排除**：仅用于提供可选项的数据不接入覆盖，也不生成有选项、无选项或选项加载场景。按用途判断，包含下拉面板、选项分组和自定义选项内容，无论通过 `options`、`children`、数组遍历或独立子组件提供，也无论来自接口、异步加载、为空或包含条件渲染。仅当用户明确要求模拟选项，或源码表明同一数据还用于控件外的独立内容区域时，才考虑接入；后一种情况只覆盖该区域的展示用途，不替换控件选项。
- 控件值若影响其他内容，先排除可直接操作且稳定可见的交互结果，再按该内容的展示差异判断；通过请求或业务计算间接产生的差异，优先覆盖最终展示结果，不模拟输入来触发业务流程。
- 通过上述排除判断后，再考虑覆盖能切换内容分支、控制区域显隐、改变展示内容或布局的数据；仅使用代码和有效业务取值支持的差异，不穷举变量或分支。

排除示例：以下 `options` 仅用于下拉选项；组件库的等价写法（如 `Select` 内渲染 `Option`）同样排除。

```tsx
<select value={position}>
  {options.map(o => (
    <option key={o.id} value={o.id}>{o.name}</option>
  ))}
</select>
```

覆盖字段使用原有状态或数据源名称，优先覆盖完整对象或数组。这里的字段名指全局覆盖对象的属性名，不要求修改源码中的变量名或解构字段。同一对象的多个展示属性共用一个覆盖字段，不按 JSX 读取的属性拆成 `objectTitle`、`objectDescription` 等字段；属性原本来自独立状态或数据源时才分别覆盖。

读取覆盖属性必须使用可选链，以 `window.__LINGSTYLE_DISPLAY_MOCK__?.xxx !== undefined` 判断是否启用；`false`、`0`、`''`、`[]`、`null` 都可能有效。每次渲染直接读取属性，不解构、缓存或重新赋值全局对象。

接入覆盖时保留原有状态、Hook 调用和解构声明，包括已有变量名、别名及 setter；不要为了腾出原变量名而新增 `originalXxx` 等别名，也不要重命名、重新赋值原状态变量。另定义本次渲染的展示变量（如 `displayedLoading`），未覆盖时回退到原值，仅在目标展示位置使用。原有数据获取、事件处理和派生计算继续使用原值。

覆盖声明须用注释标明开始和结束，开始注释概括覆盖内容及回退来源。同一组件内连续的覆盖声明共用一组注释，仅被原有业务代码隔开时分段标注。

示例：子组件通过 props 展示统计数据，在父组件的来源处选择展示值；场景仍归入统计组件。

```tsx
const Stats = ({ loading, total }) => (
  <section>{loading ? '加载中' : `${total} 个`}</section>
)

const Dashboard = () => {
  const { loading, total } = useStats()
  // 设计态展示覆盖开始：替换统计组件的加载状态和总数，未设置时使用 Hook 返回值。
  const displayedLoading =
    window.__LINGSTYLE_DISPLAY_MOCK__?.loading !== undefined
      ? window.__LINGSTYLE_DISPLAY_MOCK__?.loading
      : loading
  const displayedTotal =
    window.__LINGSTYLE_DISPLAY_MOCK__?.total !== undefined
      ? window.__LINGSTYLE_DISPLAY_MOCK__?.total
      : total
  // 设计态展示覆盖结束

  return <Stats loading={displayedLoading} total={displayedTotal} />
}
```

示例：列表经过筛选等计算时，同样保留原值及计算过程，另定义展示变量；列表内容和空状态判断使用同一个展示变量。

```tsx
const filteredUsers = useMemo(
  () => users.filter(user => user.name.includes(keyword)),
  [users, keyword]
)
// 设计态展示覆盖开始：替换筛选后的展示列表，未设置时使用原筛选结果。
const displayedUsers =
  window.__LINGSTYLE_DISPLAY_MOCK__?.users !== undefined
    ? window.__LINGSTYLE_DISPLAY_MOCK__?.users
    : filteredUsers
// 设计态展示覆盖结束

return displayedUsers.length === 0
  ? <div className={styles.empty}>暂无用户</div>
  : <div className={styles.list}>
      {displayedUsers.map(user => <div className={styles.user} key={user.id}>{user.name}</div>)}
    </div>
```

#### 四、交互脚本记录与更新

需要接入覆盖时，先完成 TSX 修改，再查看最终代码，确认组件展示位置和行号，最后更新项目根目录下的 `.agent/display-mock/interactive-scripts.yaml`。交互脚本按实际负责渲染的 React 组件定义归组；即使在上层接入 props 来源，仍归入展示状态的子组件。

文件顶层是画布数组，每项含 `canvas` 标识和 `components` 组件分组。同一组件在该画布只建一个分组，其多个状态、JSX 区域和条件分支共用 `scripts`；内部的 `div`、弹层或提示条没有独立 React 组件定义时，不另建分组。

更新前先读取 YAML，按当前画布标识精确匹配 `canvas`：已有则只更新需求涉及的组件，没有则新增画布项。禁止把其他画布项改名或作为模板覆盖；写入后核对所有非目标画布的标识、组件和场景均未改变。对目标画布，依据组件名、文件和展示 JSX 识别已有分组，合并场景并将 `loc` 更新为最终位置；不能仅因行号变化就新增重复分组。

- `title`：用简短、易懂的中文概括组件内容或功能，优先沿用画布或区域名称，否则按组件职责命名。不罗列具体场景，避免「状态」「展示」等无助于识别区域的泛称；场景细节放在 `scripts` 标题中。
- `fileName`：组件 JSX 所在的 TSX 文件路径，相对于项目根目录；
- `loc`：代表组件完整展示职责的真实 JSX 标签位置，不取局部状态标签或变量声明位置。格式为 `标签名:起始行-结束行`，如 `section:42-48`，以最终代码为准；
- `scripts`：场景数组，每项含可见名称 `title` 和可独立执行的 JavaScript `script`。脚本须重新赋值一个或多个 `window.__LINGSTYLE_DISPLAY_MOCK__` 顶层属性（如 `.users = [...]`），不能只修改对象或数组内部数据。

#### 五、场景选择规则

先按第三节选定展示数据，再确定场景集合，最后编写脚本。不为凑场景增加覆盖字段，不遍历条件分支逐条生成脚本。已在第三节排除的交互状态及其联动结果，不因默认画布尚未呈现而补充场景。用户明确指定场景时，仅生成指定场景；否则遵循以下步骤：

1. **确认默认展示与场景必要性**：结合未覆盖时的渲染路径、数据源和已有画布内容判断；异步数据不能只看 `useState` 初值。无法确认请求结果时，不臆测默认已覆盖或未覆盖哪些分支，也不以此为由补充普通数据替换场景。只补充有源码依据、与任务相关的展示结构或条件内容差异，不因文案、数值或数据规模不同就生成场景，也不添加「默认」「初始」「原始」「正常」「恢复默认」场景。仅改变数量、总数、内容长度或重复条目规模，未触发源码中明确的不同展示结构或条件内容时，不构成独立场景；除非用户明确要求，不主动构造边界或压力测试数据。
2. **按需归并列表条目差异**：先确认存在默认展示尚未覆盖、且有源码依据的条目展示差异，再将同一列表的条目类别、枚举值及内部条件区域（包括子组件）合并到一个非空列表脚本。归并规则不要求必须生成非空列表脚本，普通字段取值变化不算条目展示差异。一次赋值完整模拟数组，以足以呈现目标差异的条目数量覆盖所需内容；不为突出单个条目或子组件另建脚本，不依赖默认列表或其他脚本的数据。只有列表整体展示条件互斥、无法共存时才允许多个非空脚本，条目自身取值互斥不算。默认展示仅用于判断是否需要场景，不用于拼接模拟数据。
3. **补充整体分支**：空列表、加载、错误等按实际需要单独生成，默认已呈现的分支不重复生成。脚本须能独立呈现目标内容，必要时同时设置相关覆盖字段（例如非空列表脚本设置 `loading = false`）。

模拟数据沿用原有结构，不新增无关字段或展示分支。场景标题须概括脚本实际补充的展示差异，不能用标题将普通数据替换或无依据的规模变化包装成独立场景。写入前检查场景集合：每个脚本均须能指出其对应的源码展示条件及相对默认展示新增的内容，不能说明必要性的脚本应删除；同一列表仍有可合并的非空脚本时，先合并数据再删除多余脚本，保留所需差异。

#### 六、YAML 完整示例

沿用上面的 `Dashboard` / `Stats` 示例，假设画布根组件定义于 `/project/pages/Dashboard/index.tsx`，默认总数非零、未加载。两个场景归入同一统计组件分组；「无数据」同时关闭加载并将总数设为零：

```yaml
- canvas: page:/project/pages/Dashboard/index.tsx:Dashboard
  components:
    - title: 统计概览
      fileName: pages/Dashboard/index.tsx
      loc: "section:42-48"
      scripts:
        - title: 加载中
          script: window.__LINGSTYLE_DISPLAY_MOCK__.loading = true;
        - title: 无数据
          script: |
            window.__LINGSTYLE_DISPLAY_MOCK__.loading = false;
            window.__LINGSTYLE_DISPLAY_MOCK__.total = 0;
```

浮层画布沿用同一结构，标识按第二节生成。所有示例仅说明接入方式和记录格式，不要求接入示例字段；实际路径、组件名、行号和字段名须匹配最终代码。
